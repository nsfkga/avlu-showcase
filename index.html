What the project actually contains

Full feature and release matrix ↗
PUBLISHED PROTOTYPE

Guided listing review

A browser workflow for moving from incomplete listing details to a structured review of evidence, assumptions and next actions.

PUBLISHED BASELINE

Private Inventory Watchlist

Research records, source observations and entered cost assumptions, with export and history. Deployed owner save/export acceptance still needs final testing.

SOURCE TESTED

Bounded decision engine

Reference HOLD, REJECT, COUNTER and APPROVE states. Even a reference APPROVE cannot execute an acquisition.

SOURCE TESTED

Evidence and inspection controls

Incomplete provenance, condition and inspection submissions cannot be promoted to accepted field evidence without required proof.

SOURCE TESTED

Protected storage and recovery

PostgreSQL-backed persistence, owner access boundaries, revision checks and a disposable restore rehearsal. Production recovery acceptance is still pending.

ACTIVE DEVELOPMENT GOAL

Continuous market intelligence

Repeatable permitted data observations, verified sold comparisons and outcome-backed calibration, rather than confusing listed prices with realized profit.

    CUSTOMER DISCOVERY

    Built with the problem under investigation.

    I completed a Great Plains regional I-Corps customer discovery cohort and used operator conversations to challenge the idea that an AI valuation answer alone is enough.

    My founder-reported count is 31 dealer meetings. A separate final course log documented 23 completed discovery conversations. Those numbers are different records, not paying customers.

    What I learned and still need to test ↗
    THE CORE TEST
    Will a user make a more defensible acquisition decision, with less duplicated work and fewer missed evidence gaps, than they would using current tools?

    This is a hypothesis for a bounded user pilot, not a demonstrated revenue or savings claim.
